## 摘要
流式视频大语言模型（Streaming VideoLLMs）必须持续处理传入的视频，同时保持低查询延迟，因此视频摄入吞吐量和查询响应速度对于实时部署都至关重要。现有方法主要侧重于加速单个模块，例如视觉编码、令牌剪枝或KV缓存压缩，但关于所得系统能否维持实时流式性能的见解有限。本文将流式视频大语言模型推理形式化为一个协同流水线，涵盖视觉预处理、视觉编码、令牌丢弃以及大语言模型预填充/解码。基于这一形式化，我们提出了ViCoStream（视频协同流式处理），一个阶段协同的流式框架，结合了分块执行、CUDA流重叠、视觉令牌控制、有界视觉注意力以及查询端检索，以限制每块的计算和内存成本。我们进一步提供了瓶颈迁移的系统研究，揭示了块大小、令牌保留、注意力局部性和检索范围如何影响吞吐量-准确性权衡。在使用Qwen2.5-VL-3B/7B-Instruct的多个流式基准测试中，实验表明ViCoStream在单块A100 GPU上实现了134 FPS的视频吞吐量和低于50毫秒的首令牌时间，同时保持了接近全历史基线的准确性。

## Abstract
Streaming VideoLLMs must continuously process incoming video while maintaining low query latency, making both video-ingestion throughput and query-time responsiveness critical for real-time deployment. Existing methods largely focus on accelerating individual modules, such as visual encoding, token pruning, or KV-cache compression, but provide limited insight into whether the resulting system can sustain real-time streaming performance. We formulate streaming VideoLLM inference as a coordinated pipeline spanning visual preprocessing, visual encoding, token dropping, and LLM prefilling/decoding. Building on this formulation, we propose ViCoStream (Video Coordinated Streaming), a stage-wise coordinated streaming framework that combines chunk-wise execution, CUDA-stream overlap, visual token control, bounded visual attention, and query-side retrieval to bound per-chunk computation and memory costs. We further provide a systematic study of bottleneck migration, revealing how chunk size, token retention, attention locality, and retrieval scope shape the throughput-accuracy trade-off. Experiments with Qwen2.5-VL-3B/7B-Instruct across multiple streaming benchmarks show that ViCoStream achieves 134 FPS video throughput and less than 50 ms TTFT on a single A100 GPU while maintaining accuracy close to full-history baselines.

## 1. 论文的核心问题与整体含义（研究动机和背景）

流式视频大语言模型（Streaming VideoLLMs）需要在视频帧持续到达的过程中实时处理视频并响应查询，因此**视频摄入吞吐量（FPS）和查询首令牌延迟（TTFT）** 是两个关键系统目标。现有工作大多聚焦于加速单个模块（如视觉编码、令牌剪枝、KV缓存压缩），但缺乏对**整个流水线瓶颈迁移**的系统分析——即仅加速某个阶段可能使瓶颈转移到其他阶段，最终仍无法支撑实时流式推理。本文旨在将流式推理形式化为多阶段协同流水线，并设计出能稳定维持高吞吐、低延迟且保持高精度的框架。

## 2. 论文提出的方法论

### 核心思想
将流式视频LLM推理分解为**视觉预处理（Visual Preprocessing, VP）、视觉编码（Visual Encoding, ViT）、令牌丢弃（Token Dropping, Drop）、LLM预填充/解码（LLM Prefill/Decode）** 四个阶段，并通过**阶段级并行流水线**使不同块在不同阶段并发执行。通过联合控制各阶段的计算和内存成本，使得每块的延迟与总流长度无关，从而实现远超过100 FPS的连续摄入。

### 关键技术细节
- **分块执行（Chunk-wise processing）**：将连续帧划分为非重叠块（chunk），批处理提高ViT效率。
- **CUDA流重叠**：将GPU端的预处理（如resize、normalize）分配到独立CUDA流，与其他阶段重叠执行，避免串行化。
- **视觉令牌控制（Token Dropping）**：
  - **空间压缩**：对每帧令牌进行平均池化、最大池化或基于熵的选择，降低空间分辨率。
  - **时间压缩**：在同一块内，对每个空间位置计算帧间余弦相似度，若所有帧对相似度均高于阈值τ，则丢弃该位置的令牌；保留第一帧作为锚点。
- **有界视觉注意力（Bounded Visual Attention）**：每个视觉块只关注最近的 `acn` 个块，使得LLM预填充的KV缓存大小固定，不随流长度增长。
- **查询端检索（Query-side Retrieval）**：用户查询时，计算查询令牌与各视觉块的平均特征余弦相似度，只保留Top-k个块作为查询的可见上下文，从而限制解码阶段的注意力范围。
- **自适应训练掩码**：在训练时构造与推理时相同的注意力掩码，使视觉块只能看到最近 `acn` 个块，查询令牌只能看到检索到的块。

**公式/算法流程（文字说明）**：
1. 输入流：V = {f1, f2, ...}，分解为块 Vt = {f_{(t-1)c+1}, ..., f_{tc}}。
2. 四个阶段对不同的块并发执行（流水线）。
3. 稳态吞吐由最慢阶段决定：T_pipe = max{T_VP, T_ViT, T_Drop, T_LLM}，FPS_max = 1000 * c / T_pipe。
4. 时间令牌丢弃：若所有帧对在位置p的相似度>τ，则丢弃；空间压缩采用池化或熵选择。
5. 有界注意力和查询检索：注意力掩码 M（0或-∞）限制可见域。

## 6. 论文的主要结论与发现
- **ViCoStream可实现134 FPS视频吞吐+<50 ms TTFT**，在单A100上保持精度接近全历史基线（多数任务误差<3个点）。
- **瓶颈迁移**：当LLM侧成本降低后，视觉编码和预处理成为新瓶颈；分块大小、令牌保留率、注意力窗口应联合优化。
- **时间冗余可安全压缩**：丢弃约60-70%令牌仍可保持精度；空间压缩需谨慎（熵选择优于池化）。
- **注意力局部性有效**：每块只需关注最近4-8个块即可获得较好性能，更长窗口饱和甚至略降。
- **查询检索范围在ur=32时基本饱和**，足够覆盖相关证据。
- 长序列下，有界注意力使预填充延迟恒定，而全历史呈线性增长。
