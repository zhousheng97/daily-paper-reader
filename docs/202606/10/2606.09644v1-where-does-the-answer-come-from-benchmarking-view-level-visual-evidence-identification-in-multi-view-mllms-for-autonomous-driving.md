## 摘要
多模态大语言模型（MLLMs）在视觉推理基准上取得了显著成果，但仅靠答案准确率无法表明模型是否依赖了正确的视觉证据。这一差距对于自动驾驶中使用的多视图驾驶场景尤为重要，因为模型可能产生看似合理的答案，却将其建立在错误的摄像头视图之上。我们引入了一个多视图视觉问答基准，用于评估证据来源识别：给定六个同步的NuScenes视图和一个问题，模型必须识别出支持该问题的摄像头视图并回答问题。该基准包含来自73个场景的122个以冲突为中心的问答对，涵盖因果关系、反事实推理和意图预测。视图标签由自动冲突挖掘流水线提出，并由标注人员手动验证。我们评估了三种设置：摄像头视图选择、给定黄金视图的预言式问答，以及联合预测（模型在一次传递中选定视图并回答问题）。答案以多项选择和自由形式两种格式评估，结构化预测采用精确匹配，自由形式回答由LLM评判。通过将视觉源识别与答案正确性明确分离，该基准揭示了仅靠答案评估所遗漏的定位失败。

## Abstract
Multimodal large language models (MLLMs) achieve strong results on visual reasoning benchmarks, but answer accuracy alone does not indicate whether a model relied on the correct visual evidence. This gap is particularly important in multi-view driving scenes used for autonomous driving, where a model can produce a plausible answer while grounding it in the wrong camera view. We introduce a multi-view visual question answering benchmark for evaluating evidence-source identification: given six synchronized NuScenes views and a question, the model must identify the supporting camera view and answer the question. The benchmark contains 122 conflict-centric question-answer pairs from 73 scenes, spanning causality, counterfactual reasoning, and intent prediction. View labels are proposed by an automatic conflict-mining pipeline and manually verified by annotators. We evaluate three settings: camera-view selection, oracle QA given the golden view, and joint prediction in which the model selects a view and answers in one pass. Answers are evaluated in both multiple-choice and free-form formats, using exact match for structured predictions and an LLM judge for free-form responses. By explicitly separating visual-source identification from answer correctness, the benchmark exposes grounding failures that answer-only evaluation misses.

- **核心问题**  
  当前多模态大语言模型（MLLMs）在视觉推理基准上常以“最终答案正确率”为主要评价指标，然而答案正确并不能保证模型使用了正确的视觉证据来源。在自动驾驶的多视图场景中，同一场景的六个同步摄像头（前、前左、前右、后、后左、后右）可能各自包含不同信息，模型可能基于错误视图给出看似合理的答案，这对安全关键应用构成隐患。

## 2. 论文提出的方法论

- **核心思想**  
  构建一个面向多视图驾驶场景的视觉问答基准，强制模型在两个层面接受检验：  
  1. 从六个同步摄像头中选出含有直接视觉证据的“黄金视图”；  
  2. 基于该视图（或同时自主选择视图）给出正确答案。  
  通过分离“视图选择”与“答案推理”，可以区分模型是真正基于正确视觉信息推理，还是依赖语言捷径或错误视图。

- **关键技术细节与流程**  
  - **数据集构建流水线**（见图2）  
    - 从公开NuScenes数据集出发，通过预计算的运动学、几何和地图特征缓存数据库，挖掘六类冲突事件：行人横穿、急刹车、前车加塞、车道变更、转弯、车对车交叉路口冲突。  
    - 对每个候选事件，利用3D包围盒投影到六个摄像头平面自动判断相关参与者可见的摄像头，提出候选黄金视图。  
    - 经人工标注员审查六视图，确保：问题可由该视图充分回答、无其他视图提供同等直接证据、问题本身可回答。模糊或弱接地样本被修改或剔除。  
    - 最终保留122个冲突为中心的QA对（包含5个无可支撑视图的“无答案”样本，用于测试拒绝能力），涵盖三种推理类型：因果关系、反事实推理、意图预测。

  - **问题‑答案生成**  
    每题均可被实例化为**多项选择**（用于确定性精确匹配评分）和**自由形式**（用于测试开放式生成能力，由LLM裁判评估语义等价性）。

  - **评估设置与指标**  
    模型在零样本条件下统一评测以下三个子任务：  
    1. **视图选择**：输入六视图 + 问题，输出一个拍摄像头标签（含`NONE`表示无支撑），用准确率（Exact Match）评分。  
    2. **Oracle QA**：仅提供人工标注的黄金视图，让模型回答问题，分多项选择和自由形式，分别用精确匹配和LLM语义评分。  
    3. **联合预测**：输入六视图 + 问题，一次性输出视图、答案和简单理由。使用**严格联合正确率**：视图与答案均正确才算成功（自由形式答案由LLM裁判判定语义正确性）。  

    指标公式如下：  
    - 视图准确率：\( \text{Acc}_{\text{view}} = \frac{1}{N} \sum_{i=1}^N \mathbf{1}[\hat{v}_i = v_i^*] \)  
    - 联合严格成功：\( \text{Acc}_{\text{joint}} = \frac{1}{N} \sum_{i=1}^N \mathbf{1}[\hat{v}_i = v_i^* \land \hat{a}_i = a_i^*] \)（自由形式答案中用裁判判定语义等价替代字符串匹配）

## 6. 论文的主要结论与发现

- **答案正确性 ≠ 视觉接地正确性**  
  大量案例显示模型在选错视图的情况下仍然答对问题：在732个MC试验中，192个（超过四分之一）属于“误选视图但答案正确”，表明仅靠答案评估会大幅高估模型的视觉推理能力。

- **开源模型与商业模型差距明显**  
  视图选择准确率从Qwen2.5‑VL‑7B的12.6%到Claude的82.6%不等，多视图证据定位仍是困难任务。

- **Oracle‑to‑Joint下坠显著**  
  即使给模型正确视图（Oracle QA）时准确率较高，当要求模型自主选视图并回答（联合预测）时，严格联合正确率大幅下降。例如Claude从89.3%降至73.2%（MC），说明视图识别是端到端接地推理的主要瓶颈。

- **区域与问题类型的不平衡**  
  前视和后视图识别较好，侧视视图因相邻摄像头边界模糊而准确率低；意图预测类问题的视图识别精度往往低于因果和反事实问题。

- **弃权能力不足**  
  对于无支撑视图的样本，即便是最强模型也极少正确选择`NONE`，反映出对“无足够证据”判断的普遍困难。

## 7. 优点

- **明确分离证据源与答案质量**：打破了传统答案中心式评估的局限，揭示了模型在视觉接地上的深层问题。  
- **高质量基准构建**：基于自动冲突挖掘+人工验证的流水线，确保每个样本有单一主导的黄金视图，标注可靠。  
- **多维评估体系**：视图选择、Oracle QA、联合预测三种设置，搭配多项选择和自由形式答案，可实现粒度化诊断。

## 8. 不足与局限

- **基准规模小**：仅122个QA对，无法全面覆盖驾驶场景，更适合作为诊断工具而非全面性能标尺。  
- **数据来源单一**：基于NuScenes构建，冲突挖掘和视图分布可能受该数据集固有偏差影响。  
- **单视图标注简化**：每个问题只标记一个黄金视图，实际驾驶推理有时需要多视图整合，但为简化目标选择而未处理。
