## 摘要
长视频理解通常将视频压缩为少量帧或视觉标记以生成答案。现有的紧凑型流程侧重于保留相关的视觉内容作为显式证据。然而，使证据可用并不能确保跨时刻的互补线索被整合用于回答。我们的关键思想是在生成之前将选定的帧组织成与查询相关的跨帧证据。我们将这一后选择阶段表述为一个潜在证据接口，并用GenEvA（生成式潜在证据聚合）实例化，这是一个分布引导的潜在证据聚合框架。具体来说，GenEvA使用查询条件下的证据分布将聚合集中在相关帧上，从其帧特定信息形成紧凑的跨帧潜在证据。由于并非总是需要跨帧整合，相同的分布决定是否插入这种潜在补充。在四个基准测试和两个Video-MLLM主干网络上，GenEvA持续改进匹配帧基线。在8帧时，它将四个基准测试的LLaVA-Video平均分提高了+5.2分，Qwen2.5-VL在LVBench上的准确率提高了+10.1分。这些提升仅需平均0.11%–0.40%的视频标记开销；分析进一步显示了任务感知分配和自适应证据调用的益处。

## Abstract
Long-video understanding commonly compresses videos into a small set of frames or visual tokens for answer generation. Existing compact pipelines focus on retaining relevant visual content as explicit evidence. Yet making evidence available does not ensure that complementary cues across moments are integrated for answering. Our key idea is to organize selected frames into query-relevant cross-frame evidence before generation. We formulate this post-selection stage as a latent evidence interface and instantiate it with GenEvA ($\textbf{Gen}erative$ $Latent$ $\textbf{Ev}idence$ $\textbf{A}ggregation$), a distribution-guided latent evidence aggregation framework. Specifically, GenEvA uses a query-conditioned evidence distribution to focus aggregation on relevant frames, forming compact cross-frame latent evidence from their frame-specific information. Since cross-frame integration is not always needed, the same distribution determines whether to insert this latent complement. Across four benchmarks and two Video-MLLM backbones, GenEvA consistently improves matched-frame baselines. At 8 frames, it raises the four-benchmark LLaVA-Video average by $+5.2$ points and Qwen2.5-VL accuracy on LVBench by $+10.1$ points. These gains require only $0.11\%$--$0.40\%$ average video-token overhead; analyses further show task-aware allocation and benefits from Adaptive Evidence Invocation.

### 1. 核心问题与整体含义（研究动机与背景）

- **研究动机**：长视频理解通常依赖将视频压缩为少量帧或视觉 token 来生成答案。现有方法多聚焦于“如何选出相关帧”或“如何压缩视觉输入”，即构建 **显式视觉证据**。然而，**证据可用并不等于证据被有效使用**——即便相关帧已被选出，多模态大模型仍可能忽略视觉线索，转而依赖语言先验或上下文偏差（如幻觉问题）。论文通过诊断发现：即使选出的帧与标注证据高度重合，显式-only 的 Video-MLLM 在超过半数问题上仍回答错误，说明存在一个 **后选择瓶颈（post-selection bottleneck）**：证据到达模型后，未被可靠地转化为与答案相关的表示。
- **核心问题**：如何从选定的帧中构建 **查询相关的潜在证据（query-relevant latent evidence）**，以补充显式视觉上下文，从而让模型真正“使用”跨帧互补线索？
- **整体含义**：论文主张在帧选择与答案生成之间增设一个 **潜在证据接口（latent evidence interface）**，作为紧凑长视频理解管线中缺失的一环。该接口保留显式视觉上下文，同时额外注入紧凑的、跨帧聚合的潜在证据通道，从而提升答案生成的准确性。

### 2. 方法论：核心思想、关键技术细节、流程

- **核心思想**：将后选择阶段组织为“潜在证据接口”，实例化为 **GenEvA（生成式潜在证据聚合）** 框架。GenEvA 对选中的帧进行查询条件化的潜在证据分配与聚合，并依据分配分散度决定是否注入这些潜在证据。
- **总体流程**：
  1. 使用冻结的预训练时序选择器按帧预算 K 选出关键帧（显式上下文）；
  2. 冻结的视觉塔提取帧级视觉特征；
  3. **证据预算分配（Evidence-Budget Allocation）**：将每个帧与问题计算兼容性得分，经 softmax 归一化为分配分布 α，再通过确定性取整（BudgetAssign）转换为每个帧的整数 token 预算 n_i；
  4. **查询感知的潜在证据聚合（Query-Aware Latent Evidence Aggregation）**：利用问题到视觉的交叉注意力获得共享查询-视觉上下文 c_qv，再用可训练潜在基与条件化 MLP 为每帧生成可变长度潜在证据束，拼接后附加到显式输入序列，经冻结 LLM 上的 LoRA 适配器整合为最终潜在证据 E；
  5. **自适应证据调用（Adaptive Evidence Invocation）**：依据分配残差的 ℓ2 分散度 s_disp 决定是否注入潜在证据；分散度 > 1/2 时走“显式+潜在”路线，否则仅走显式路线。
- **关键公式**：
  - 分配分数归一化：α_i = exp(r_i/τ_a) / Σ_j exp(r_j/τ_a)；
  - 分配分散度：s_disp(n) = (1 - Σ_i p̃_i²) / (1 - 1/K)，其中 p̃_i = (n_i − 1)/(B − K)；
  - 训练目标：使用多项采样进行比较，结合归一化得分函数代理、平均潜在对数似然与裕度项，联合优化分配器与证据适配器，保持 LLM 骨干冻结。
- **算法本质**：用同一查询条件分配分布控制 **潜在容量分配** 与 **是否调用潜在证据**，无需额外训练路由模块。

### 6. 主要结论与发现

- GenEvA 在四个基准、两个骨干上 **一致提升匹配帧基线**：8 帧下 LLaVA-Video 四基准平均 +5.2 分（Qwen2.5-VL 在 LVBench 上 +10.1 分）；16 帧下平均 +3.4 分。
- 开销极低：解码端视频 token 开销仅 **0.11%–0.40%**，推理延迟增幅约 +2.0%（2.790 → 2.847 s/例）。
- 帧效率高：8/16 帧 + GenEvA 可超越 64 帧均匀采样，甚至匹配或超过 Vamba 的 1024 帧结果。
- 分配具有 **任务感知性**：分布式证据任务（如 MLVU 全局任务、LVBench 摘要类）的分配分散度显著高于局部证据任务（如单点细节、实体识别）。
- 自适应调用优于 Full/Random 调用，说明路由信号有实际收益；显式与潜在两条路线在 7,703 个配对样本上显示出明显互补性（潜在-only 正确 16.1%，显式-only 正确 12.1%）。

### 7. 优点

- **问题定义新颖**：明确区分“证据可获得”与“证据被使用”，提出后选择阶段的潜在证据接口，属于多数方法忽视的空白地带。
- **设计简洁高效**：同一查询条件分配同时控制潜在容量与路由决策，避免了额外训练路由器的开销。
- **开销极低、收益显著**：相比长上下文的 1024 帧方法（如 Vamba），以 8–16 帧 + 32 潜在 token 的极小成本取得更好或相当的结果。
- **评估扎实**：多基准、多骨干、多帧预算、路径互补性分析、分配模式分析、token 与延迟核算、敏感性分析均较完整。
- **保持了模型的冻结性**：无需修改骨干 LLM，适配器参数轻量，便于集成到已有 Video-MLLM 流程中。

### 8. 不足与局限

- **训练数据单一**：仅在 LLaVA-Video-178K 的 8,000 样本上训练；未系统评测训练数据规模对任务适配广度的依赖。
- **依赖冻结的时序选择器**：若选择器质量下降或域分布变化，GenEvA 的框架性收益可能随之退化；对选择器与适配器的联合敏感性未分析。
- **潜在 token 预算仅取 32**：虽然敏感性分析显示 512 个潜在 token 收益有限，但未系统分析不同基准/任务对 B 的最优值，固定 32 可能并非普适最优。
- **二值化路由阈值的约束**：固定阈值为 1/2 在标注跨度分析（如 LVBench 实体识别分散度为 0.40 仍然正确）与实证上有一定依据，但未必在所有任务族上最优；不同任务的最优路由边界可能连续而非二值。
- **有效支持数解释**：阈值 1/2 对应的有效帧支持数约 2 帧，但未深入讨论哪些任务需要恰好 2 帧、哪些需要更多帧；对 3–5 帧等中间分配形态的边界行为未充分研究。
- **未报告训练时长与收敛曲线**：算力之外的训练细节和超参敏感性不透明。
- **偏向长视频 QA 场景**：未在在线视频流、交互式问答、多轮对话或长视频摘要等场景中验证。
